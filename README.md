## 功能特性

### 起播与媒体信息

- **预提取媒体信息**：入库前/后自动探测，播放时无需等待 ffprobe，显著提升起播速度
- **独占提取模式**：接管 Emby 原生 ffprobe 与截图，可自定义 ffprobe（支持 rffmpeg 分布式提取）
- **ISO 直读**：Linux/Docker 下由自定义 ffprobe 直接读取 UDF 镜像，支持 MPLS 播放列表语言与章节解析
- **信息持久化**：媒体信息落盘为 `*-mediainfo.json`，支持备份/恢复/清理后重新提取
- **图像捕获**：视频截图、预览缩略图、背景图生成（含多选后处理）
- **HDR 标注**：识别 CUVA 动态元数据，把画质标签显示为 `HDR Vivid`；双层杜比视界按增强层标注 Profile 7
- **并发与超时控制**：1–20 并发、可配置超时与截图超时倍数

### 片头片尾

- **声纹探测**：提取音频指纹，基于 Emby 原生片头检测
- **行为探测**：根据播放行为自动标记片头片尾
- **在线刮削**：从 IntroDB / Tidb 自动同步片头片尾标记，支持按库、按剧批量刮削
- **手动干预**：单集/整季标记、清理、重新探测

### 多版本

- **自动合并**：同目录或多库中的同名视频自动合并为多版本，不强制官方命名规范
- **展示增强**：标签显示画质档位、视频编码、码率与体积（如 `4K HEVC 46.1Mbps 168.4MB`）
- **排序**：按画质、体积、路径排序，支持自定义显示格式
- **删除前预览**：删除整季某版本前，可先查看会删掉哪些文件、哪些因版本身份不明被跳过

### 元数据增强

- **中文元数据**：自定义 TMDB / TVDB 备选语言与回退顺序
- **豆瓣辅助**：评分覆盖、演员中文名、名称与简介、海报兜底；季级匹配带标题主体校验与映射缓存
- **剧集组刮削**：支持 TMDB 剧集组、本地剧集组 JSON
- **人物增强**：提取演员别名、导入季演职人员、合并剧集演职人员
- **海报与排序**：原语言海报优先、拼音首字母排序、NFO 增强、清除标语
- **本地元数据缓存**：`override/` + `cache/` 双层结构，可离线重建媒体库
- **刮削优化**：按季获取单集元数据、跳过逐集兜底与集图片请求

### 搜索与网络

- **中文搜索增强**：SQLite FTS5 + libsimple 分词器，支持中文模糊搜索与拼音搜索
- **代理与直连**：HTTP 代理、本地服务发现、影音直链重定向
- **TMDB 替换**：可替换 TMDB 接口地址

## 设置页结构

插件设置分为 6 个 Tab，顶部提供**插件总开关**（关闭后不加载补丁、不订阅事件、不初始化队列，修改后需重启服务器）：

| Tab | 主要内容 |
|---|---|
| 基础设置 | 插件总开关、任务并发、内存管理、中文搜索、界面功能、运行状态与维护 |
| 高级功能 | 多版本合并与展示、播放与清理、通知、条目显示、媒体库与排序、搜索与日志 |
| 媒体信息 | 提取范围、图像捕获、ISO 提取、HDR 标注、信息持久化、性能与独占 |
| 元数据 | 中文元数据、剧集组、刮削优化、人物增强、豆瓣辅助、海报与排序、元数据刷新、本地元数据缓存 |
| 片头片尾 | 声纹探测、行为探测、在线刮削 |
| 网络代理 | 网络与本地发现、影音直链、TMDB 替换 |

设置页左上角提供**选项搜索**，输入关键词即可过滤定位选项。

## 定时任务

| 合并多版本 | 扫描并合并同片多版本 |

| 刷新演职人员 / 删除演职人员 | 人物信息维护 |
| 扫描外挂字幕 | 独立扫描外部字幕文件 |

## 兼容性说明

插件采用动态适配机制：启动时检测 Emby 版本，优先使用 Harmony 补丁，不可用时回退反射，再回退公共 API。

| Emby 版本 | 兼容状态 | 备注 |
|---|---|---|
| 4.10.2.x | ✅ 完全支持 | 当前适配与实测版本 |
| 4.10.1.x | ✅ 完全支持 | 已实测（旧基线） |
| 4.10.0.x | ✅ 完全支持 | 已在 x64 实测（全部模块 Harmony + 中文搜索增强） |
| 4.9.1.90+ | ✅ 完全支持 | 推荐版本，性能最优 |
| 4.9.1.0–89 | ✅ 支持 | 部分功能可能降级 |
| < 4.9.1.0 | ❌ 不支持 | 已移除兼容逻辑 |

| 架构 | 兼容状态 | 备注 |
|---|---|---|
| x86-64 / x64 | ✅ 完全支持 | 所有功能可用 |
| ARM64 / aarch64 | ✅ 完全支持 | 需 Harmony 2.4.2+，含中文搜索增强 |

## 构建说明

### 方式一：GitHub Actions（推荐）

CI 支持两种触发方式：

- **推送标签自动构建**：`git push origin v3.0.0.73` 即自动构建并发布对应版本（会校验标签名与工程版本号一致）
- **手动触发**：在 GitHub 仓库的 Actions 页面选择 `Build Plugin`，点击 `Run workflow` 执行

构建完成后从 [Releases](https://github.com/wabisabi926/StrmAssistant/releases) 下载对应版本 tag（如 `v3.0.0.73`）的 `StrmAssistantPlus_v<版本>.dll`，重命名为 `StrmAssistantPlus.dll` 覆盖到 `config/plugins/StrmAssistantPlus.dll` 后重启 Emby。

> 插件文件名固定用 `StrmAssistantPlus.dll`。如果插件目录里还存在 `StrmAssistant.dll` 之类的旧副本，请一并删除——两个文件并存时 Emby 会同时加载，表现为重复插件。

### 方式二：本地构建

- 需要 .NET 6.0 SDK 或更高
- Linux 下请使用 `build-local.sh`（绕开 Resource.Embedder 的 Linux 路径问题）

```bash
bash build-local.sh
```

构建产物：`StrmAssistant/bin/Release/StrmAssistant.merged.dll`，复制到插件目录时命名为 `StrmAssistantPlus.dll`。

### 编译 libsimple.so（中文/拼音分词器）

源码与一键脚本位于 `StrmAssistant/Tokenizer/libsimple-src/`，详见该目录 README。
